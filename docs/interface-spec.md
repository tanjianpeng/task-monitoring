# 跑批监控接口规范

## 1. 接口总览

本期建议收敛为 2 类核心接口：

1. 本地查询接口
2. 统一任务动作上报接口

其中：

1. 前端每 1 分钟调用一次本地查询接口。
2. 各业务系统在任务开始时调用统一接口的 `begin` 动作。
3. 各业务系统在任务结束时调用统一接口的 `end` 动作。
4. 业务系统不支持重跑接口调用。
5. 日志记录只放在统一动作上报接口上，本地查询接口不记录调用日志。

## 2. 接口清单

### 2.1 本地查询接口

- 接口名称：查询大屏任务状态
- 请求方式：`GET`
- 接口路径：`/api/monitor/local/queryTaskStatus`
- 调用方：前端大屏
- 调用频率：每 1 分钟一次
- 接口说明：从本地数据库查询当天任务运行情况，并在查询时实时计算任务状态

状态计算建议：

1. `PENDING`：未开始，当前时间未超过计划开始时间
2. `DELAYED`：未开始，当前时间已超过计划开始时间
3. `RUNNING`：已收到开始时间，未收到结束时间
4. `TIMEOUT`：已开始未结束，且当前时间已超过预计结束时间
5. `SUCCESS`：已收到结束时间，结束结果为成功
6. `FAILED`：已收到结束时间，结束结果为失败

### 2.2 统一任务动作上报接口

- 接口名称：统一任务动作上报
- 请求方式：`POST`
- 接口路径：`/api/monitor/task/{params}`
- 调用方：各业务系统
- 接口说明：任务开始、结束通过同一个接口调用，通过路径参数区分动作

路径参数说明：

1. `begin`：任务开始
2. `end`：任务结束

#### 2.2.1 `begin` 开始动作

处理动作：

1. 校验系统编码和任务编码
2. 写入调用日志
3. 更新任务实例开始时间
4. 更新任务当前状态为 `RUNNING`
5. 计算预计结束时间

#### 2.2.2 `end` 结束动作

处理动作：

1. 校验系统编码和任务编码
2. 写入调用日志
3. 更新任务实例结束时间
4. 更新执行结果状态
5. 计算实际耗时
6. 成功则更新为 `SUCCESS`
7. 失败则更新为 `FAILED`

## 3. 日志记录建议

建议只在调用类接口中记录日志，不在查询接口中记录：

1. 新增 `monitor_task_log` 日志表
2. `begin` 调用时记录一条开始日志
3. `end` 调用时记录一条结束日志

日志建议字段：

1. 请求流水号
2. 调用URL
3. 系统编码
4. 任务编码
5. 业务日期
6. 接口类型
7. 请求报文
8. 返回结果
9. 调用时间

## 4. 返回规范

建议 3 个接口统一返回结构：

```json
{
  "code": "0000",
  "message": "success",
  "data": {}
}
```

其中：

1. `0000` 表示成功
2. 非 `0000` 表示失败
3. 失败时返回明确错误信息，方便业务系统定位问题
